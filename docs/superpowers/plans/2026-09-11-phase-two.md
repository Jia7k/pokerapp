# Phase 2 Implementation Plan

> **For agentic workers:** Use test-driven implementation and independent review. Tasks have disjoint source ownership.

**Goal:** Add offline preflop/postflop strategy and the observable PokerViewModel.

**Architecture:** Pure strategy engines in PokerCore consume validated game values. The main-actor view model validates UI inputs and publishes a complete derived analysis.

**Tech Stack:** Swift 6, Observation, Swift Package Manager, XCTest.

**Spec:** `docs/superpowers/specs/2026-09-11-phase-two-design.md`

## Global Constraints

- Phase 2 only; no SwiftUI screens yet.
- iOS 17+, macOS 14+, no external dependencies or APIs.
- Six-seat, heads-up decision presets; transparent approximations, no solver-GTO or win-equity claims.
- Preserve all Phase 1 behavior.

## Tasks

- [x] Preflop: canonical StartingHand, Position, StackDepth, PreflopSituation, PreflopChartAction and complete PreflopStrategy dictionary; write category/coverage/action tests before implementation. Owner: preflop agent.
- [x] Shared betting values: validated BettingState, ActionRecommendation and bounded actions, plus pot/stack tests. Owner: root.
- [x] Postflop: BoardTextureAnalyzer and PostflopHeuristicEngine with board-contribution-aware made-hand assessment; test action ordering and draw horizons. Owner: postflop agent.
- [x] ViewModel: validated card slots, observation, analysis snapshot and chart-to-legal-action adaptation; test state transitions and integration. Owner: root.
- [x] Final verification: independent review, all Swift tests and iOS Simulator compile; README examples and boundaries. Owner: root.

## Coordination and decisions

The directory is not a Git repository. Work remains in the user-selected workspace. Agents own disjoint files; root owns shared contracts and integration. The preflop chart action is a sizing intent, and the ViewModel converts it into a legal chip amount using BettingState. Postflop returns the shared ActionRecommendation directly. This separates chart presets from current chip state.

## Completion evidence — 2026-09-11

- Full release suite with `POKER_EXHAUSTIVE_TESTS=1`: 108 tests passed, zero failures or skips, including all 2,598,960 five-card combinations.
- Swift 6 iOS Simulator compilation passed with warnings treated as errors. The binary identifies IOSSIMULATOR with minimum iOS 17.0. The compiler used its documented `-disable-sandbox` subprocess option because this workspace cannot nest a second sandbox for Observation macros.
- Independent whole-phase review approved the final source with no unresolved actionable findings.
- Numeric regression tests verify cancellation-safe short calls, finite all-in sizing, chart depth endpoints, and safe overflow fallbacks.
- Decision refinement: use exact one-card completion probability for ordinary flop calls and all turn calls, retaining Rule of 2/4 as the displayed heuristic and Rule of 4 for closing flop calls. This resolves ambiguous initial turn wording and avoids a false fold at a 19% price with nine turn outs.
- Further review fixes distinguish hero-owned weak pairs from board-only categories, recognize guaranteed board splits, and explain coverage-limited checks accurately.
- Phase 3 SwiftUI screens remain the next delivery.
